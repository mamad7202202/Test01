GUIDES / Troubleshooting

Troubleshooting and common questions

Most connection problems come from an endpoint, model ID, or network setting that does not match the selected provider. Check these items before changing anything else.

The model does not connect

Confirm the API key is current and allowed to use the model. Verify the base URL includes the expected API path, then check whether the model ID is available to your account.

A local model is unreachable

On a phone, localhost points to the phone. Use your computer’s LAN address, start the local server, and allow network access through the computer firewall. Both devices need a route to each other.

The APK will not install

Use an APK asset from the project Releases page. On most phones choose the ARM64 build; use universal if the device architecture requires it. Android may require permission to install apps from the browser or file manager.

The update banner does not appear

The updater checks for newer version-numbered releases that include an APK. It skips the rolling latest tag. Use Settings → Check for updates or install a release APK manually.

Can I reset memory?

Use the memory manager to inspect entries. /clear removes stored facts and outline bullets but keeps the standing MEMORY.md rules file. Removing app data is a broader Android action and may erase local sessions and settings too.

Where can I report a problem?

The repository currently has no open issues. Review the source and release notes, then open a GitHub issue with the app version, Android version, provider type, and a short reproduction. Do not include API keys or private conversation text.

Note

Provider errors are returned by the configured service. Check that provider’s status and documentation when its API reports a rate limit or model error.
